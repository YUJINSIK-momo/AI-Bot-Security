# 보고서 형식

보고서에는 그 서비스의 약점이 담긴다. 공개 저장소 · 공개 채널에 올리지 않는다. 저장 위치는 `.bot-defense.json` 의 `report_dir` 이나 사용자에게 묻는다.

```markdown
# <서비스> 봇 방어 점검 — <YYYY-MM-DD>

## 한 줄 결론
<지금 가장 큰 구멍 하나와 먼저 할 일 하나>

## 스택
| 층 | 무엇 | 근거 |
|---|---|---|
| 앞단 | 예: ALB(WAF 없음) | detect-stack · aws-inventory |
| 앱 | 예: Next.js + NestJS | package.json |

## 공격자가 보는 것
- 번들에 보이는 API 경로 n개(대표 몇 개)
- 소스맵: 열림 / 닫힘
- 번들의 키: 종류와 할 일(도메인 제한 등)
- robots.txt: AI 봇 n개 중 n개 막음

## 지금 막는 것
| 경로 · 기능 | 인증 | 상한 | 비싼 호출 |
|---|---|---|---|

## 구멍 (높음 → 낮음)
| # | 위험 | 위협(T1~T6) | 근거(파일:줄 · 점검 결과) | 영향 |
|---|---|---|---|---|

## 대응안
| 순서 | 할 일 | 막는 위협 | 비용 | 누가 정하나 | 바꾸는 곳 |
|---|---|---|---|---|---|
| 1 | 예: robots.txt | T1 · T2 | 0 | 개발자 | 코드 PR |

## 하지 않을 것
- 예: JS 난독화 — 분석 도구에 효과 없음

## 결정이 필요한 것
- 예: 상세 데이터를 로그인 뒤로 둘지(기획)

## 다음 점검
- 예: Count 모드 1주 뒤 log-watch 로 규칙별 수 확인
```

규칙:
- 근거 없는 주장은 쓰지 않는다. 모르는 것은 「확인 필요」.
- 비용은 확인 날짜와 함께 쓴다.
- IP 원문 · 계정 ID 전체 · 키 값은 쓰지 않는다.
