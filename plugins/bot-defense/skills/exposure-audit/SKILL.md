# 노출 점검

결과는 「구멍 목록」(위험도 · 위협 T1~T6 · 근거 · 영향)이다. 위협 정의는 `${CLAUDE_PLUGIN_ROOT}/references/threats.md`.

## A. 코드 — 공개 경로 표

1. 프레임워크별로 경로를 모은다(`stack-detect` 결과의 framework 와 `${CLAUDE_PLUGIN_ROOT}/references/frameworks/` 문서).
   - Next.js: `app/**/route.ts`, `pages/api/**`, Server Actions(`"use server"`)
   - NestJS: `@Controller` + `@Get/@Post…`, 전역 prefix, 전역 가드
   - Express · Fastify: `app.get/router.get…`, 플러그인 등록
   - Django · FastAPI · Flask: URL 설정 · 데코레이터
2. 경로마다 적는다.

   | 경로 | 인증 | 상한 | 비싼 호출 | 일괄 · 열거 | 근거(파일:줄) |
   |---|---|---|---|---|---|

   - **인증:** 서버에서 막는가. 화면에서만 막으면 「화면만」이라고 적는다(가장 흔한 구멍).
   - **상한:** 있으면 기준(IP · 계정 · 전체), 창, 저장 위치(메모리 · 공유), 프록시 뒤 IP 를 어떻게 얻는지.
   - **비싼 호출:** LLM SDK · 유료 외부 API · 무거운 쿼리. 캐시가 있으면 크기와 「새로 만들 때만 상한」 여부.
   - **일괄 · 열거:** 한 요청이 여러 항목을 주는지(batch), 인자가 코드 · 순번이라 훑기 쉬운지.
3. 함께 본다.
   - 서버 내부 클라이언트(서버 렌더러 · PDF 헤드리스 브라우저)가 공개 경로를 부르는지 — IP 상한이 그걸 막는 함정
   - LLM 전체 상한이 공격으로 바닥나 실제 사용자가 막히는지
   - 설계 문서에 「서버는 공개, 화면이 막는다」 같은 결정이 있는지(있으면 근거로 인용하고, 바꿀지는 결정 항목으로)
   - robots.txt · 약관의 자동 수집 금지 조항 · 로그인 동의 기록
   - 소스맵 설정, 브라우저로 나가는 환경 변수 이름(`stack-detect` 의 `public-env-names`)

## B. 운영 사이트 — 공격자 시점

1. **먼저 확인받는다:** 이 주소가 사용자 것(또는 점검 권한이 있는 것)인지.
2. 돌린다(요청 30번 안팎, 읽기만):

   ```
   ${CLAUDE_PLUGIN_ROOT}/scripts/probe-site.sh --url <운영 주소> --authorized
   ```

   - 속도 제한이 실제로 걸리는지 보고 싶을 때만, 사용자가 고른 공개 경로 하나에 `--burst /경로 --count 30` 을 더한다(최대 60). 운영 부하 · 경보를 울릴 수 있으니 먼저 묻는다.
3. 읽는 법:
   - `robots`: AI 봇 중 몇 개가 막혔나, `*` 의 Disallow
   - `bot_user_agent_test`: 봇 이름으로 보낸 요청이 앞단에서 막히는지(이름만 흉내 낸 것이라 검증 규칙에는 안 걸릴 수 있다)
   - `bundle.source_maps.exposed`: 비어 있어야 한다
   - `bundle.api_paths_visible`: 분석 도구가 바로 얻는 API 목록 — A 의 표와 맞춰 본다
   - `bundle.keys`: `HIGH-secret-in-bundle` 이면 **즉시** 알리고 키 교체를 권한다. 지도 · 분석 키는 도메인 제한 확인을 권한다

## 위험도

- **높음:** secret 이 번들에 있음 · 로그인 없이 LLM 을 부르는 경로에 상한이 없음 · 값진 데이터를 대량으로 주는 경로가 상한 없이 공개(화면만 막음 포함)
- **중간:** 상한은 있으나 메모리 · 프록시 IP 처리가 약함 · 내부 클라이언트 함정 · 소스맵 열림 · 키 도메인 제한 없음
- **낮음:** robots.txt 없음 · 약관 조항 없음 · 앞단 봇 규칙 없음(앱 상한이 있을 때)
